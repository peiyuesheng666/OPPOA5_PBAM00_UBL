# OPPOA5_PBAM00_UBL

OPPO A5 PBAM00 / eMMC / 匹配的官方 A.03。

## 使用

1. 解压整个资料包，运行「一键安装依赖和驱动.cmd」。首次安装 Python 需要联网。
2. 手机进入 9008，仅连接目标手机。
3. 双击「一键解锁.cmd」或「一键回锁.cmd」。回锁先显示红色警告，输入 y 回车才继续。
4. 保持连接，等待脚本执行结束，在手机重启后查看锁状态。

回锁前须恢复匹配的官方 A.03 全量固件及原厂启动分区；脚本不会检查 boot/recovery/vbmeta，也不会自动降级。

解锁后如需清除数据，请在 Recovery 操作，此操作会删除个人内容。脚本不读取或备份 userdata，改变锁状态可能导致数据不可用。

## 启动链与解锁思路

### 原厂开机流程

`上电 → PBL → SBL → aboot / LK → boot 镜像 → Linux 内核与 init → Android 系统`

PBL 加载并认证后续引导镜像，SBL 初始化硬件，aboot 选择启动模式。正常启动时，aboot 从 boot 分区加载内核和 ramdisk，再进入 Android。

### 为什么针对 A.03

SBL 镜像、钩子位置及函数地址按 A.03 适配，不能直接套用到 A.35。两版均有安全启动和签名校验。

### RAM 代码包含什么

上传的是带临时钩子的完整 A.03 SBL 镜像和启动跳板。跳板将 SBL 各段放到对应内存位置并执行；钩子接入内存中的 aboot，调用原厂锁状态设置函数。修改版 SBL 不写入 sbl1 分区。

### 为什么放进 RAM 可以执行

Firehose 的内存写入能力用于上传代码并重定向返回位置，转入 RAM 启动跳板，绕开修改版 SBL 的正常加载验签入口。这不是破解签名算法，也不会关闭所有后续校验。

### 解锁与回锁流程

`进入 9008 → 加载 Firehose → 上传 RAM 启动跳板与修改版 SBL → 接入 aboot → 调用原厂状态设置逻辑 → 继续启动`

主解锁标志：`1` 为已解锁，`0` 为已锁定，由原厂逻辑保存。

临时代码在断电后消失，持久锁状态保留。Bootloader 解锁不等于取得 Android root 权限。
