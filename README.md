# OPPO A5 PBAM00 Bootloader 解锁

解锁方案/脚本/文件 By 酷安@Dev裴月笙 公益解锁文件，禁止倒卖盈利

适用于 **OPPO A5 PBAM00、eMMC、匹配的 A.03 固件**。不支持直接在 A.35 上运行；已解锁的设备无需重复执行。

## 使用方法

1. 下载并完整解压资料包，保持文件结构。
2. 双击 `一键安装依赖和驱动.cmd`，按向导安装高通驱动并允许管理员提示。脚本自动准备 Python 环境和 pyserial；缺少 Python 时尝试通过 winget 联网安装。
3. 只连接目标手机，进入新的一次 9008 模式，双击 `一键解锁.cmd`。
4. 按窗口提示依次完成三轮。前两轮结束后需要手动强制重启、重新进入 9008，再按回车继续。
5. 第三轮等待 900E 时保持连接，不要重启。验证结束后再手动强制重启手机。

脚本不自动降级、不刷整包、不读取或备份 userdata。解锁过程会请求写入持久状态，不能保证数据可用性。请提前准备本机恢复材料，不要使用其他手机的 NV 或校准备份。

## 三轮分别做什么

| 轮次 | 操作 | 对应资料目录 |
| --- | --- | --- |
| 第一轮 | 在 RAM 引导中调用原厂主解锁 setter | `partition-analysis/ram-unlock-trace09/` |
| 第二轮 | 调用原厂高层状态读取函数，记录状态 | `partition-analysis/ram-unlock-trace10/` |
| 第三轮 | 独立启动后直接读取 keymaster 后端，验证持久状态 | `partition-analysis/ram-unlock-trace11/` |

目录名保留以兼容现有脚本，文档和窗口统一使用第一、二、三轮。

第二轮的高层读取函数在状态头无效时可能初始化并持久化默认状态，因此不能把它视为完全只读。目前没有验证省略第二轮是否仍能成功。

## 成功判据

第三轮必须同时读到：

- 追踪记录有效。
- keymaster `0x202` 读取返回 `0`。
- 状态头为 `ANDROID-BOOT!`。
- `main_unlocked = 1`。

本机实测主解锁字段为 `1`，critical 字段为 `0`。这确认主锁状态，不代表 critical 解锁或任意未签名镜像均可启动。

原机刷回 A.35 后，用户确认系统正常启动且仍为解锁状态；升级后结果来自用户实机确认，未取得独立的 A.35 后端查询。

## 工作原理

9008 加载 `firehose_450.mbn` 后，通过内存读写暂存并执行修改过的 A.03 SBL。SBL 加载 aboot 后修改其 RAM 执行流程，在原厂 keymaster 加载完成后调用原厂状态函数。第三轮直接调用 `0x202` 后端读取，不调用 setter、默认初始化函数或 `0x203` 写入接口。

第三轮主动触发诊断异常进入 900E，电脑只读取两个 128 字节合成记录。此时黑屏是诊断流程的一部分，不要提前重启覆盖记录。

## 常见问题

| 现象 | 处理 |
| --- | --- |
| 等待 9008 超时 | 检查驱动、数据线及手机模式，只连接目标设备 |
| Sahara 读取包头为 0 字节 | 未完成握手；关闭其他工具，强制重启并重新进入 9008。持续失败时保留日志，检查是否已运行 Firehose |
| 固件不匹配 | 停止使用；不要绕过检查或将 A.03 地址用于 A.35 |
| 第二屏、Recovery 或黑屏 | 不能单凭画面判断解锁成功，以第三轮读取结果为准 |
| 第三轮进入 900E | 保持连接等待自动读取，验证结束后手动重启 |
| 程序报错 | 保留 `runs/` 下本次日志，不自动重试解锁 |

离线自检（不访问手机）：

```powershell
python one_click_unlock.py --self-check
```
