# OPPOA5_PBAM00_UBL

[English](README_EN.md)

**必须先将手机降级至匹配的 A.03 固件，再运行解锁脚本。脚本不会自动降级。**

仅适用于 OPPO A5 PBAM00（eMMC）。不能在 A.35 或其他不匹配版本上直接运行；已解锁的设备无需重复执行。

## 使用方法

1. 下载并完整解压资料包，保持文件结构。
2. 双击 `一键安装依赖和驱动.cmd`，按向导安装高通驱动并允许管理员提示。脚本自动准备 Python 环境和 pyserial；缺少 Python 时尝试通过 winget 联网安装。
3. 只连接目标手机，进入新的一次 9008 模式，双击 `一键解锁.cmd`。
4. 脚本自动完成固件检查、RAM 暂存及第一轮启动请求，然后结束。
5. 若手机停在异常画面，手动强制重启。该精简版不再执行后续状态处理与持久解锁验证，完成提示不代表已解锁。

脚本不自动降级、不刷整包、不读取或备份 userdata。解锁过程会请求写入持久状态，不能保证数据可用性。请提前准备本机恢复材料，不要使用其他手机的 NV 或校准备份。

## 单轮流程

仅执行原第一轮：在 RAM 引导中调用原厂主解锁 setter。资料位于 `partition-analysis/ram-unlock-trace09/`。

第二轮和第三轮已移除。本精简流程尚未独立实机验证，不能保证只执行第一轮即可完成解锁，也不会自动确认持久解锁状态。

## 工作原理

9008 加载 `firehose_450.mbn` 后，通过内存读写暂存并执行修改过的 A.03 SBL。SBL 加载 aboot 后修改其 RAM 执行流程，在原厂 keymaster 加载完成后调用原厂状态函数。

## 常见问题

| 现象 | 处理 |
| --- | --- |
| 等待 9008 超时 | 检查驱动、数据线及手机模式，只连接目标设备 |
| Sahara 读取包头为 0 字节 | 未完成握手；关闭其他工具，强制重启并重新进入 9008。持续失败时保留日志，检查是否已运行 Firehose |
| 固件不匹配 | 停止使用；不要绕过检查或将 A.03 地址用于 A.35 |
| 第二屏、Recovery 或黑屏 | 不能单凭画面判断解锁成功，需另行检查设备实际解锁状态 |
| 程序报错 | 保留 `runs/` 下本次日志，不自动重试解锁 |

离线自检（不访问手机）：

```powershell
python one_click_unlock.py --self-check
```
